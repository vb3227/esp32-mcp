# Быстрая установка готового .bin

Релиз содержит два семейства: минимальное ESP32 MCP и полное UNIHIKER K10. В публичных образах нет Wi-Fi-паролей, API-ключей или MCP-токенов автора. Настройки вводятся по USB и сохраняются в NVS самой платы.

## Выбор образа

| Устройство | Каталог | esptool --chip |
| --- | --- | --- |
| ESP32 DevKit / WROOM-32 | esp32dev | esp32 |
| ESP32-S3 DevKitC-1 | esp32s3 | esp32s3 |
| ESP32-C3 DevKitM-1 | esp32c3 | esp32c3 |
| ESP32-C6 DevKitC-1 | esp32c6 | esp32c6 |
| ESP32-S2 Saola-1 | esp32s2 | esp32s2 |
| ESP-WROVER-KIT | esp32wrover | esp32 |
| UNIHIKER K10 | k10 | esp32s3 |

Не выбирайте образ только по наличию ESP32 в названии. Сверьте конкретную плату, chip и объём flash с flash-plan.json. Все профили используют разные бинарники. Минимальные сборки не содержат драйверов камеры, экрана, микрофона и ASR K10.

## Установка

1. Распакуйте esp32-mcp-firmware.zip. Проверьте SHA256SUMS.txt, например `Get-FileHash firmware/k10/factory.bin -Algorithm SHA256`.
2. Установите Python, esptool и pyserial: `python -m pip install "esptool>=5,<6" pyserial`.
3. Подключите USB-кабель с передачей данных и закройте Serial Monitor. Определите порт через `python -m serial.tools.list_ports`.
4. Для **первой установки** запишите factory.bin своего профиля по адресу 0x0. Пример K10:

```powershell
python -m esptool --chip esp32s3 --port COM5 write-flash 0x0 firmware/k10/factory.bin
```

Замените COM5 и профиль. Если подключение не начинается, используйте BOOT/RESET по инструкции производителя. Не отключайте проверку соответствия чипа.

**factory.bin включает загрузчик, таблицу разделов и приложение. Заполнение промежутков может очистить NVS и существующие настройки. Используйте его для первой установки, а не обычного обновления.** Это поведение raw merged image описано в [документации esptool](https://docs.espressif.com/projects/esptool/en/latest/esp32/esptool/basic-commands.html).

Для обновления уже установленного проекта с той же таблицей разделов используйте только firmware.bin приложения по адресу из flash-plan.json (у текущих профилей 0x10000):

```powershell
python -m esptool --chip esp32s3 --port COM5 write-flash 0x10000 firmware/k10/firmware.bin
```

Не выполняйте erase-flash для обычного обновления: оно удаляет настройки, навыки и другие данные.

## Настройка без пересборки

На первом запуске чистый образ ожидает конфигурацию по USB; сеть/MCP пока отключены. Из каталога скачанного проекта запустите:

```powershell
python scripts/configure_device.py --port COM5
```

Введите SSID и Wi-Fi-пароль. Программа создаст два независимых случайных токена, отправит конфигурацию, дождётся подтверждения и перезагрузки платы. Сам пароль не печатается и не сохраняется в host-файл. MCP-переменные сохраняются в приватный `.esp_mcp/device-settings.json`; **не публикуйте этот файл**. На Windows ограничьте доступ к нему своей учётной записью.

Перенесите значения из этого файла в локальную конфигурацию MCP-клиента. Задайте ESP_MCP_BOARD_URL по IP платы и ESP_MCP_CONNECTION=direct либо настройте relay по [руководству](MCP_SETUP_RU.md). Для K10 используйте --profile k10; для остальных --profile generic. Облачные ключи нужны только опциональным host-сервисам, их не надо отправлять на плату.

Сохранённая USB-конфигурация имеет приоритет над параметрами компиляции. Для смены сети повторно запустите помощник: он заменяет токены, поэтому обновите их и в MCP-клиенте. Настройки в NVS не шифруются этой прошивкой; физический доступ к flash позволяет их прочитать.

## ASR-модель K10

Обычный K10-образ не включает сторонние ASR-модели и не перезаписывает существующий раздел модели. На плате с уже установленной совместимой английской моделью местные команды сохраняются. Если модель отсутствует, один раз используйте vendor-профиль k10_model_en через PlatformIO, затем обычный k10. Сеть/MCP доступны и без ASR-модели. Не применяйте полное стирание flash, если хотите сохранить модель.

## Воспроизведение релиза

```powershell
python scripts/build_firmware_release.py --pio pio --jobs 2
```

Скрипт копирует только публичные исходники в `.esp_mcp/release-workspace`, создаёт пустой board_config.h из шаблона и собирает каждый профиль отдельно. Рабочий приватный заголовок не меняется и не используется. Адреса flash берутся из PlatformIO, пересечения сегментов запрещены, известные локальные секреты проверяются перед упаковкой. Результаты: `dist/firmware/` и `dist/esp32-mcp-firmware.zip`.

Компиляция подтверждает совместимость с toolchain, а не проверку всех физических вариантов платы. Актуальные аппаратные проверки находятся в [TESTING.md](TESTING.md).
