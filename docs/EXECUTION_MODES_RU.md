# Где исполняется код

| Режим | Исполнитель | Хранение | Возможности |
| --- | --- | --- | --- |
| JSON | C++ операции платы | Каталог ноутбука, опционально NVS | Готовые аппаратные действия, композиция |
| Python | Ограниченный процесс ноутбука | Исходник/manifest, приватное JSON-состояние | Функции, циклы, условия, вычисления и MCP |
| Lua | Виртуальная машина ESP32 | Исходник/manifest, опционально NVS | Локальные циклы, разрешённые GPIO/I2C/SPI |

MCP — протокол вызова инструментов. Модель создаёт код, сервер проверяет формат и передаёт исполнителю. После установки этой прошивки новые Lua-программы сохраняются и запускаются без перепрошивки. Python остаётся на ноутбуке, не на микроконтроллере.

Lua убирает сетевой запрос для каждой итерации и может продолжать запущенную задачу без ноутбука. Цена — ограниченные RAM/CPU, 32-битные числа и общий с прошивкой процесс. Ошибка VM/драйвера способна повлиять на всё устройство. Для неизвестной периферии нужны правильная электрическая схема и доступный интерфейс: Lua не устанавливает нативные драйверы автоматически.

Python уже поддерживает полноценную логику через API `device`, но без произвольных импортов, shell, файлов и сокетов. Эти ограничения уменьшают случайные ошибки, не гарантируя изоляцию враждебного кода. Не запускайте недоверенные программы ни в одном исполнителе.

Сохраняйте проверенный навык с короткой фразой и алиасами. Число повторений JSON-навыка меняйте композицией. Автоматическое применение произвольных параметров к любому исходнику Lua/Python не реализовано.
